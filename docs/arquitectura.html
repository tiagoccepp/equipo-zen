2. Ciclo de Vida de un Mensaje

Cada vez que escribís o hablás, esto es lo que pasa por dentro:

Fase 1: Recepción

1
El usuario escribe "Hola Julio, ¿cómo va?" o presiona el micrófono
2
El WebSocket recibe el mensaje tipo user_turn
3
MeetingSession.enqueueUserTurn() agrega el turno a la cola de procesamiento
4
Se guarda en MeetingMemory y se envía user_turn_received al cliente

Fase 2: Orquestación (¿Quién responde?)

5
AgentRouter.route() evalúa el mensaje con heurística: detecta saludos, cierres, menciones directas y dominios
6
Si es saludo o grupo, el IA Router decide con Gemini quiénes hablan
7
Se envía route_decision con los targets seleccionados

Fase 3: Respuesta de Agentes (secuencial)

8
Se ejecuta un for sobre los targets. Primero el agente con mayor score.
9
generateText(): Llama a gemini-3.1-flash-lite con el system prompt (identidad + tareas + protocolo) y el prompt del turno
10
Se envía agent_transcript_delta con el texto (streaming al UI)
11
generateAudio(): Llama a gemini-2.5-flash-preview-tts para generar voz
12
Se envían agent_audio_chunk con PCM → PcmAudioQueue reproduce la voz
13
processAgentTaskCommands(): Parsea etiquetas [TAREA_CREAR] y [TAREA_COMPLETAR]
14
Se envía agent_turn_complete con la respuesta final

3. Orquestador (AgentRouter)

Decide qué agente responde. Usa un sistema de dos capas:

Capa 1: Heurística (rápida, local)

  • Detecta saludos (isGreetingTurn)
  • Detecta cierres ("gracias", "perfecto")
  • Detecta menciones directas ("Julio", "Tomasa")
  • Detecta si se habla al grupo ("chicos", "equipo")
  • Compara dominios contra palabras del mensaje

Capa 2: IA Router (inteligente, remota)

  • Solo para saludos o grupo addressed
  • Envía contexto a Gemini para decidir
  • Retorna JSON con targets y razón
  • Timeout: 4.5 segundos

Flujo de Decisión

Mensaje del usuario
        │
        ▼
¿Es cierre? ──SÍ──► Devuelve último agente que habló
        │
       NO
        ▼
¿Es saludo? ──SÍ──► Devuelve todos los agentes (o los mencionados)
        │
       NO
        ▼
¿Grupo? ──SÍ──► IA Router decide quiénes
        │
       NO
        ▼
Evalúa por agente:
  +8 pts  Mencionaron su nombre
  +2 pts  Cada palabra de sus dominios
  +1 pt   Señal de colaboración
  +1 pt   Es una pregunta
        │
        ▼
¿Score >= 4? ──SÍ──► Agente responde
        │
       NO
        ▼
Nadie responde (sin inventar)

4. Los Agentes (LiveAgentRuntime)

Cada agente tiene su propia instancia con tres responsabilidades principales:

generateText()

Genera la respuesta de texto. Construye un system prompt con la identidad del agente, sus tareas, y reglas de comportamiento. Llama a gemini-3.1-flash-lite.

generateAudio()

Convierte el texto a voz con gemini-2.5-flash-preview-tts. Retorna chunks de PCM que el frontend reproduce.

processAgentTaskCommands()

Parsea etiquetas especiales en la respuesta: [TAREA_CREAR: id: desc] y [TAREA_COMPLETAR: #n]. Actualiza el tablero de tareas.

5. Sistema de Claves (ApiKeyRing)

6 claves Gemini con rotación automática y cooldown:

acquire():
  1. Empieza en cursor
  2. Por cada key:
     ¿cooldownUntil <= ahora?
       SÍ ──► La devuelve, avanza cursor
       NO ──► Siguiente key
  3. Si todas en cooldown ──► Retorna null

reportFailure(key, error):
  key.failures += 1
  ¿Error de cuota (429)?
    SÍ ──► cooldown = 1 hora
    NO ──► ¿Permanente?
      SÍ ──► cooldown = 24 horas
      NO ──► cooldown = 45 segundos

reportSuccess(key):
  key.failures = 0
  key.lastError = null

7. Protocolos

Protocolo de Turnos

  • Los agentes responden secuencialmente (uno a la vez, nunca al mismo tiempo)
  • Si el orquestador selecciona 2 agentes, primero habla el que tiene mayor score
  • El contextual followup solo se activa si el otro agente es mencionado por nombre

Protocolo de Tareas

Los agentes pueden crear y completar tareas autónomamente:

Agente dice: "Armo la API [TAREA_CREAR: programacion: Implementar endpoint de login]"
                                        │
                                        ▼
El servidor parsea la etiqueta
Crea la tarea en el agente "programacion"
Actualiza la UI
Limpia la etiqueta del texto visible

Protocolo de Silencio

  • Si un agente no debe hablar, no genera respuesta
  • No envía "SILENCIO" como texto visible
  • El orquestador simplemente no lo incluye en los targets

Protocolo de Cierre

  • Cuando el usuario dice "gracias", "perfecto", "dale", etc.
  • Solo responde el último agente que habló
  • Confirma breve que entendió y no abre nuevos temas
